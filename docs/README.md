# Unfiled Product Documentation

This directory is the planning and implementation-reference set for **Unfiled**. Milestones A, B, and the credential-free portion of Milestone C are complete. C.5a supplies encrypted-schema expansion and managed-key custody; C.5b adds typed encrypted aggregates and managed adapters; C.5c supplies separate organizer, index-worker, and strict-decrypt-verifier runtimes; and C.5d wires the complete encrypted repository/search/export/retention surface plus an explicit irreversible plaintext-storage contract. Milestone D supplies the organizer's production cipher, encrypted RAG retrieval/selection, conservative routing policy, strict provider adapters, a deterministic production-component evaluation seam, and optional explicit-key live runners in code. Milestone E0–E4 supply the shared interaction foundation, owner-authorized encrypted correction/Review/batch Undo, encrypted explicit and learned routing-rule personalization, separately encrypted generated blocks, non-destructive duplicate suggestions, immutable AI settings, Vault-only BYOK, and live-lease credential resolution; PR #15, #16, and #17 recorded their required CI lanes green on 2026-09-01. Milestone F (the dedicated hybrid-search trust domain, exact database boundaries, web/native search and note-context surfaces, structured-log editing, streaming export, and atomic account deletion) merged into `main` as PR #18 at `e09f9554e2fee8acd454363a5a411cb9bf8e5c6d` on 2026-09-02 with a successful post-merge CI run. Milestone G is in progress on the current branch: it adds [ADR-0015](./decisions/ADR-0015-user-selectable-provider-model-effort.md) dual-provider BYOK (independent OpenAI and Claude keys in Vault, provider → model → effort selection, strict OpenAI Responses and Claude Messages adapters, registry `organization-model-registry-v2`), [ADR-0016](./decisions/ADR-0016-free-beta-vercel-sensitive-key-custody-and-local-hash-retrieval.md) free-beta custody (`vercel-sensitive-env-v1` root ring, `unfiled-local-hash-v1` retrieval, AWS KMS deferred), public trust routes, status/roadmap/architecture/operations documentation, and migrations `20260902000000`/`20260902000001` (clean local reset, 43 pgTAP files / 2,033 assertions). The D seam still excludes database lease/heartbeat, encrypted seal/persist, and repository select/commit generation revalidation, and no credentialed live routing run has been executed for either provider. Live deployment, remote migration, provider-key, canary, backup, signing, archive, and physical-device evidence is recorded in `FINAL_REPORT.md` per `HUMAN_SETUP.md`. The irreversible storage contraction stays un-applied on the free plan, app-funded AI is not offered, AI-assisted search is lexical-strength local-hash retrieval rather than semantic search, and no E2EE claim is made.

The current private-beta deployment topology intentionally uses one free remote Supabase project
(`Unfiled Preview`, `us-west-2`) as the Production database; local Supabase remains Development,
and Vercel Preview deployments are intentionally not built so no second custodian targets the shared
database. Workload-specific least-privilege PostgreSQL roles remain distinct. Separate remote
databases, paid PITR, and AWS KMS custody are deferred, and the irreversible encrypted-storage
contraction stays blocked until its restore gate can be proven. See [STATUS.md](./STATUS.md),
[ROADMAP.md](./ROADMAP.md), and [ARCHITECTURE.md](./ARCHITECTURE.md) for the claim-safe current
view.

## Milestone C.5a boundary

C.5a is an expand-only security foundation, not the encrypted-library release gate. It adds owner/class/purpose/version-bound intermediate-key records; four distinct KMS root families with exact-context policies; web-versus-worker OIDC identities; encrypted-column and content-free RAG/job schema; a separately deployable worker that accepts only an exact trusted web caller; and the `unfiled_index_worker` PostgreSQL role with no login, RLS bypass, inherited role, table, sequence, or private-schema capability. Its runtime allowlist is exactly six RAG RPCs. Root rewrap remains a service-only, locked CAS operation and is unavailable to the worker. See [ADR-0007](./decisions/ADR-0007-dedicated-worker-database-capability-and-root-rewrap.md).

The checked-in tests can prove policy shape and fail-closed behavior without credentials. They cannot prove the deployed Vercel header path, STS exchange, direct private-KMS denial, CloudTrail capture, production database connection identity, key rotation, or backup restore. Those account-bound checks remain pending in [HUMAN_SETUP.md](../HUMAN_SETUP.md).

## Milestone C.5b boundary

C.5b implements the application-side typed encrypted aggregate and strict service-only database capabilities described in [ADR-0008](./decisions/ADR-0008-encrypted-aggregate-rollout-and-replay.md). The database owns stable write identities, wrap reservations, request-MAC replay claims, exact revision compare-and-swap, envelope projections, verification evidence, resumable owner-scoped backfill, and only the `expanded → dual_write → encrypted_read` portion of rollout. Managed adapters create fresh callback-scoped custody/runtime clients and do not fall back to the legacy repository when an encrypted operation fails.

The private-manual capture branch can seal and persist its source and receipt through the encrypted aggregate. C.5c supplies the atomic organizer database and application boundary for AI-assisted captures, and Milestone D composes the production cipher, encrypted per-owner retrieval, strict provider plan, deterministic extraction/preservation, and conservative create-or-append policy behind it. C.5d composes the complete encrypted repository behind authoritative rollout state; pre-contract states retain a deliberate rollback adapter, while state/RPC/KMS errors never downgrade to it. Checked-in implementation still does not imply that Production has executed the global contract or passed a real-provider routing gate.

The C.5c index slice implements the encrypted index capability contract, strict float32 encrypted payload codec, bounded exact-scan retrieval/ranking primitives, a managed-cloud index worker, resumable shadow-generation maintenance, and an independent decrypt-only verifier. Preview and Production each require their own exact, same-environment Vercel, provider, and AWS identities; neither can fall back to a local bearer or synthetic key authority. The private beta explicitly reuses the one remote database and each workload's narrow login across both managed scopes. Within either environment, worker and verifier still use different identities: the worker retains six RAG RPCs and AI object-wrap key generation/decryption, while the verifier has exactly two RPCs and AI object-wrap decryption only. The verifier's fixed admission capacity is 1,000 notes: 33 pages provide 1,023 physical worst-row slots under the fixed ciphertext budget, deliberately capped at the accepted retrieval gate; larger libraries defer without repeatedly creating bad generations. A separate fixed four-key-record limit bounds KMS work. The historical C.5c-2 focused evidence is 158 worker tests, 436 web tests, 168 verifier unit tests plus the dedicated 1,000-document capacity gate, 13 Terraform tests, and a clean 23-file / 1,185-assertion database run.

### Milestone C.5c organizer boundary

`apps/organizer` is a fourth Vercel trust domain, distinct from web, index worker, and verifier. Production web sends only `{"trigger":"schedule|recovery|manual"}` to the exact proved `unfiled-organizer` origin with a short-lived Vercel OIDC token that the organizer's checked-in app-level verifier checks (Preview is not built). The organizer rejects cross-environment subjects, browser sessions, local bearer secrets, cookies, `Authorization`, protection-bypass credentials, request-supplied owner IDs, broad Supabase credentials, static AWS credentials, private-manual keys, and ambient provider keys. `UNFILED_ORGANIZER_OPENAI_API_KEY` is optional and funds only OpenAI app-default routing; the free beta sets none, so app-default jobs fail closed to Inbox. The live-lease Vault resolver supplies one user OpenAI or Claude key transiently for the provider snapshotted on the job. Its own deadline is at most 49 seconds; an organization commit atomically enqueues content-free index work, and both managed environments deliberately leave that queue to the independent index-recovery path rather than chaining a second long-running worker request.

The exact PostgreSQL login is `unfiled_organizer_worker`: initially `NOLOGIN`, `NOINHERIT`, and `NOBYPASSRLS`, with no relation, sequence, private-schema, or public-create privilege. Through E3 it executed exactly ten job/lease-scoped functions. E4 adds only `get_lease_bound_organizer_provider_credential`, making the current allowlist exactly eleven: claim, heartbeat/revalidate, bounded candidate projection, encrypted-RAG pagination, exact ranked-candidate selection, prepare create, prepare append, atomic commit, fail, stale-job recovery, and live-lease credential resolution. The database derives ownership from the live lease, issues stable IDs and key reservations, and allows one replan before forcing Review. The organizer's key subset is limited to the AI-assisted object-wrap and content-MAC roots (Vercel Sensitive root ring in the free beta; AWS KMS deferred) and it cannot use private-manual roots or rewrap a root.

Production and development invoke only the isolated organizer; deterministic organization is an explicit test fixture, not a deployed fallback. Milestone D connected the production cipher, encrypted exact-scan RAG candidate path, strict OpenAI planner, and policy/materialization boundary; Milestone G adds the strict Claude Messages planner (one forced tool, `output_config.effort`) and the registry-v2 model/effort snapshot. The OpenAI Responses call is foreground, tool-free, and `store: false`; that flag is not a Zero Data Retention guarantee. Retrieval uses `unfiled-local-hash-v1` in process and makes no embedding request. C.5d has switched application reads/writes/search/export/retention to encrypted adapters and implemented removal of plaintext columns/indexes as a separate database-owner operation. The live evaluations for both providers, remote migrations, database-login, root-ring, canary, and backup evidence are recorded in `FINAL_REPORT.md` per `HUMAN_SETUP.md`; the contraction remains deferred.

Milestone D historically discarded model-returned generated-expansion text. E3 now closes that gap: organizer prepare/commit atomically persists a separate encrypted `proposed` generated block and encrypted pending-expansion Review while leaving user-authored note content unchanged. The owner-authorized web service and native client list those blocks outside editable note text; accept retains the generated block with provenance, reject hides it, and both leave the note revision unchanged. Owner-visible reads are note-scoped, use ascending block-ID keyset pagination with a 51-row lookahead for exact 50-item pages, and filter rejected rows before applying the keyset and limit. Review uses an exact generated-block read instead of scanning the owner library. Public list/detail schemas admit only `proposed` and `accepted`; the resolve response may carry the resulting `rejected` state without making rejected content readable afterward. Rejected blocks become purge-eligible after seven days through the existing encrypted-retention capability. Duplicate suspicions are encrypted Review items containing an explanation and two or three current revision-bound note choices; only `Keep both` and `Dismiss` are available, and neither mutates a note. E3 adds only `resolve_encrypted_generated_block` to the public database surface and leaves the isolated organizer at exactly ten RPCs. E1 and E2 retain their correction, Review, batch-Undo, and private-rule boundaries. E4 implements [ADR-0012](./decisions/ADR-0012-vault-only-lease-bound-byok-credentials.md): exact owner settings and provider-key CRUD, Vault-only storage, secret-free job snapshots, transient exact Vault comparison for PUT replay, and the sole eleventh organizer RPC. Milestone G extends it under [ADR-0015](./decisions/ADR-0015-user-selectable-provider-model-effort.md): OpenAI and Claude keys are stored independently and addressed per provider, the Claude adapter is implemented, and each job snapshots provider, model preference, resolved model ID, and effort. Production BYOK evidence (key entry through the UI and live canaries) is recorded in `FINAL_REPORT.md`.

## Rules for maintaining this set

- A change to scope, schema, or contract lands in the owning document in the same change set as the code, never after.
- BUILD_PLAN.md stays the summary; when it disagrees with a companion document on a detail, the companion document wins and BUILD_PLAN.md gets corrected.
- Every non-obvious decision gets an ADR; ADRs are never edited after acceptance, only superseded.
- Open questions move from OPEN_QUESTIONS.md into an ADR when decided; they are not deleted.
