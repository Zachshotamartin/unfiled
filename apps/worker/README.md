# Unfiled isolated worker

This package is the separately deployable encrypted-index trust domain introduced by C.5a/C.5c. It exposes only JSON health and content-free drain endpoints. It has no page renderer, browser bundle, user-session parser, global Supabase credential, or private-manual key selector.

The managed-cloud composition is executable in Preview and Production. It connects only as `unfiled_index_worker` over verified TLS, calls the exact six reviewed RAG RPCs, opens only owner/revision-bound `ai_assisted` ciphertext through request-scoped KMS custody, obtains a model-bound embedding, seals the retrieval document, revalidates the lease/privacy/revision boundary, and commits the ciphertext. Ambiguous state transitions replay the exact same serialized request once; lease recovery owns any remaining uncertainty.

## Local run

Copy `.env.example` values into your local environment, replace the drain secret with a random value of at least 32 characters, then run:

```sh
pnpm --filter @unfiled/worker dev
```

The local server listens on `127.0.0.1:8788` by default. A drain request has no content payload beyond an optional trigger:

```sh
curl -X POST http://127.0.0.1:8788/internal/drain \
  -H "Authorization: Bearer $UNFILED_WORKER_DRAIN_SECRET" \
  -H "Content-Type: application/json" \
  --data '{"trigger":"manual"}'
```

Indexing is disabled only in local development. Preview and Production require complete, explicitly scoped Vercel identity, exactly one managed key custodian (see "Key custodian modes"), database, and embedding configuration and fail startup when any part is absent or inconsistent. For the private beta, the two managed scopes deliberately reuse one `unfiled_index_worker` login in one remote Supabase project; this is not database isolation. Vercel identity, custody, and embedding configuration remain environment-specific. The managed custodian cannot be replaced by the local synthetic authority; use dependency-injected tests and a disposable exact-role database integration for credential-free development evidence. There is no plaintext, bearer-secret, synthetic-key, or global-credential fallback in either managed environment.

## Key custodian modes

`UNFILED_KEY_CUSTODIAN` must be exactly one of two values in Preview and Production. The value is compared without trimming, so surrounding whitespace fails.

| Mode                      | Root keys                                                     | Managed-key records  | Free-beta status                                   |
| ------------------------- | ------------------------------------------------------------- | -------------------- | -------------------------------------------------- |
| `vercel-sensitive-env-v1` | AES-256 roots held in a Vercel Sensitive Environment Variable | V2 (`rootKeyId` URN) | Used for the $0 beta                               |
| `aws-kms`                 | AWS KMS roots reached through Vercel OIDC and STS             | V1 (`rootKeyArn`)    | Preserved as deferred paid hardening; not required |

In `vercel-sensitive-env-v1` mode the worker accepts exactly:

- `UNFILED_WORKER_PROJECT_ID`, matching `^prj_[A-Za-z0-9]+$` and byte-identical to the injected `VERCEL_PROJECT_ID`.
- `UNFILED_WORKER_AI_OBJECT_WRAP_ROOT_KEY_ID`, one root ID matching `^urn:unfiled:key-root:vercel-sensitive-env-v1:(preview|production):<RFC-4122 UUID>$` whose environment segment equals `UNFILED_WORKER_ENV`.
- `UNFILED_VERCEL_SENSITIVE_ENV_ROOT_KEY_RING_V1` (Sensitive), at most 32,768 bytes of canonical JSON with exactly the keys `deploymentEnvironment`, `projectId`, `roots`, and `version: 1`. Its `projectId` and `deploymentEnvironment` must equal the injected `VERCEL_PROJECT_ID` and `VERCEL_ENV`, and its `roots` must contain exactly the active root plus every retired root below, each with a distinct 43-character base64url `keyMaterial` of exactly 32 bytes. A ring minted for another project or environment is rejected before any key is imported.
- Optional `UNFILED_WORKER_RETIRED_AI_OBJECT_WRAP_ROOT_KEY_IDS_JSON`, default `[]`: a canonical JSON array of at most 20 distinct same-environment root IDs that never includes the active root. Retired roots are unwrap-only.

The same mode rejects `UNFILED_AWS_REGION`, `UNFILED_AWS_ROLE_ARN`, `UNFILED_AI_OBJECT_WRAP_KMS_KEY_ARN`, `UNFILED_RETIRED_AI_OBJECT_WRAP_ROOTS_JSON`, and `UNFILED_WORKER_EXPECTED_OIDC_SUBJECT`, and at ring-open time additionally requires `NODE_ENV=production` and rejects `AWS_ROLE_ARN`, any `UNFILED_*_AWS_ROLE_ARN`, `UNFILED_LOCAL_KEY_RING_V1`, and any `NEXT_PUBLIC_*` name containing `KEK`, `MASTER_KEY`, `ROOT_KEY`, `KEY_BYTES`, `KEY_MATERIAL`, or `KEY_RING`. `aws-kms` mode rejects the three `vercel-sensitive-env-v1` variables in return, so the two custodians can never be configured together. No `x-vercel-oidc-token` workload header is used in `vercel-sensitive-env-v1` mode; if the adapter is handed one it fails closed.

Before any authority is issued in `vercel-sensitive-env-v1` mode, the adapter performs an in-memory readiness round trip: it generates a throwaway intermediate key under the active root, unwraps an activated copy of that record, and compares the bytes. The worker then receives the `index_worker` custody role, which can generate and unwrap AI-assisted object-wrap keys only; the search service and verifier receive the unwrap-only role and cannot mint keys. Managed-key records written in this mode are schema V2 (`custodyProvider: "vercel_sensitive_environment_v1"`, `wrapAlgorithm: "AES-256-GCM"`, a 65-byte `UFEK` envelope) and are never parsed by the AWS path; AWS V1 records are never parsed by this path.

Honest limits: in `vercel-sensitive-env-v1` mode the root material is an exportable environment value present in the function process. There is no HSM, no per-call cloud audit record, and no IAM denial between workloads; the software role split and Vercel project separation are the boundary. This protects AI-assisted content against a database-only disclosure. It is neither end-to-end encryption nor zero knowledge in either mode: this worker decrypts AI-assisted content by design, and private-manual keys never reach it.

## Embedding modes

`UNFILED_WORKER_EMBEDDING_PROVIDER` must be exactly `local-hash-v1` or `openai`.

`local-hash-v1` is the free-beta profile. It fixes the generation model ID to `unfiled-local-hash-v1` and the dimensions to 512, and rejects `UNFILED_OPENAI_EMBEDDING_API_KEY`, `UNFILED_EMBEDDING_MODEL_ID`, and `UNFILED_EMBEDDING_DIMENSIONS`, so no provider key exists in the process and no note text leaves it for retrieval. The vector is deterministic feature hashing from `@unfiled/search`: normalized words, adjacent-word pairs, and character trigrams land in signed buckets of an L2-normalized float32 vector. It is an honest lexical retrieval signal, not an AI semantic embedding: two notes match only to the extent that they share wording, so paraphrases and synonyms do not match, and its relevance is weaker than a semantic embedding. A generation carrying this model ID must never be presented as semantic search evidence. `UNFILED_EMBEDDING_MAX_INPUT_BYTES` (1,024–65,536) and `UNFILED_EMBEDDING_TIMEOUT_MS` (1,000–30,000) still bound the in-process step.

`openai` requires all of `UNFILED_OPENAI_EMBEDDING_API_KEY`, `UNFILED_EMBEDDING_MODEL_ID`, and `UNFILED_EMBEDDING_DIMENSIONS` and sends AI-assisted projection text to the fixed OpenAI embeddings endpoint.

In both modes the drain only indexes into a generation whose recorded model ID and dimensions equal the configured profile, and a returned vector whose length differs from the generation's dimensions fails closed; a profile change therefore requires a new generation rather than silently mixing vectors.

## Separate Vercel project

Create a Vercel project whose Root Directory is exactly `apps/worker`. Do not reuse the web/API project. Enable Secure Backend Access (OIDC) for this worker project and keep the project ID in `UNFILED_WORKER_PROJECT_ID`. The committed `api` entries use Vercel's Node Web Handler interface, and `vercel.json` enables cancellation plus a 60-second platform ceiling.

Enable Vercel's automatic System Environment Variables. Managed startup requires exact `VERCEL=1`, `VERCEL_ENV`, `VERCEL_DEPLOYMENT_ID`, and lowercase full `VERCEL_GIT_COMMIT_SHA` values. Every response includes `x-unfiled-deployment` as a SHA-256 digest of the trimmed deployment ID plus exact `x-unfiled-commit` and `x-unfiled-environment`; the raw deployment ID is never returned. These are release-consistency checks, not proof that an alias belongs to this Vercel project.

Preview and Production each need explicitly scoped worker values. In every item below, `<environment>` is the exact selected value, `preview` or `production`; credentials and resources must not be copied between scopes except for the documented private-beta database values that intentionally target the same remote project:

- `UNFILED_WORKER_ENV=<environment>` and Vercel's own `VERCEL_ENV=<environment>`; Vercel must also inject `VERCEL=1`.
- `UNFILED_KEY_CUSTODIAN`, exactly `vercel-sensitive-env-v1` (free beta) or `aws-kms`. The next four AWS items apply only to `aws-kms`; the `vercel-sensitive-env-v1` items are listed under "Key custodian modes".
- (`aws-kms` only) `UNFILED_AWS_REGION` and an `UNFILED_AWS_ROLE_ARN` dedicated to the worker workload.
- (`aws-kms` only) `UNFILED_AI_OBJECT_WRAP_KMS_KEY_ARN`, set to the one full active AI-assisted object-wrap ARN emitted by infrastructure. Aliases, raw IDs, a legacy singular key ID, any AI content-MAC variable/registry, and every private root fail closed. The ARN must match the role's AWS partition/account and configured region.
- (`aws-kms` only) `UNFILED_RETIRED_AI_OBJECT_WRAP_ROOTS_JSON`, normally `[]`, or a duplicate-free JSON array of at most 20 full retired AI object-wrap ARNs. Copy it verbatim from `terraform output -raw worker_retired_ai_object_wrap_roots_json`; never hand-transform a broader registry. Active, staged, content-MAC, private, cross-account/partition/region, duplicate, object-shaped, and alias entries are rejected. Readiness probes the active object-wrap root only; runtime unwrap accepts only the validated retired object-wrap roots while rewrap completes.
- (`aws-kms` only) `UNFILED_WORKER_EXPECTED_OIDC_SUBJECT`, equal to the one exact same-environment worker subject in the AWS role trust condition. Its `project:` segment contains the exact Vercel project **name** (for example `unfiled-worker`), not the `prj_...` project ID, and it ends in `:environment:<environment>`.
- `UNFILED_WORKER_PROJECT_ID`, exactly matching Vercel's injected `VERCEL_PROJECT_ID`.
- `UNFILED_TRUSTED_SOURCE_TEAM_SLUG`, `UNFILED_TRUSTED_SOURCE_OWNER_ID`, `UNFILED_TRUSTED_SOURCE_WEB_PROJECT_ID`, `UNFILED_TRUSTED_SOURCE_WEB_PROJECT_NAME`, and `UNFILED_TRUSTED_SOURCE_EXPECTED_OIDC_SUBJECT`, all describing the separate same-environment web deployment that invokes this worker. The source project ID and name must differ from the worker's, and the source subject must exactly equal `owner:<team-slug>:project:<web-project-name>:environment:<environment>`.
- `UNFILED_WORKER_DATABASE_URL`, using the Supabase shared-pooler transport username `unfiled_index_worker.<project-ref>` and `sslmode=verify-full`; the separately pinned `UNFILED_WORKER_DATABASE_EXPECTED_HOST` and `UNFILED_WORKER_DATABASE_PROJECT_REF`; and `UNFILED_WORKER_DATABASE_CA_PEM_BASE64`, containing the canonical downloaded CA chain. The private beta enters the same four values in both managed scopes. A direct or dedicated-pooler `db.<project-ref>.supabase.co` endpoint instead uses the unsuffixed role. The parser derives the only acceptable transport username from the endpoint class and exact 20-character project ref, and rejects tenant drift, IP literals, alternate users/databases, credentials outside the URL, ambiguous paths/parameters, and hostname mismatch. Every pooled session independently proves both PostgreSQL `session_user` and `current_user` are the unsuffixed exact worker role before use.
- `UNFILED_WORKER_EMBEDDING_PROVIDER`, exactly `local-hash-v1` (free beta; no provider key exists) or `openai`. `openai` additionally requires `UNFILED_OPENAI_EMBEDDING_API_KEY`, `UNFILED_EMBEDDING_MODEL_ID`, and `UNFILED_EMBEDDING_DIMENSIONS`; `local-hash-v1` rejects all three. The fixed OpenAI endpoint is `https://api.openai.com/v1/embeddings`; redirects, unbounded input/output, unexpected response fields, model/dimension mismatch, and non-finite values fail closed. Only AI-assisted note projection text is ever sent, and only in `openai` mode. Private-manual content is rejected by the database before claim and is never opened or submitted. See "Embedding modes" for the relevance limits of the local hash profile.
- Optional bounded controls: `UNFILED_INDEX_CLAIM_LIMIT` (maximum 4), `UNFILED_INDEX_CONCURRENCY` (maximum 4 and no greater than the claim limit), `UNFILED_INDEX_LEASE_SECONDS`, `UNFILED_INDEX_RECOVERY_LIMIT`, database connect/statement timeouts, and embedding input/timeout limits. Configuration fails closed unless a conservative cold-path budget fits inside the worker deadline: pool connection and identity verification, every critical-path RPC and its identity query, one exact terminal replay, all serial provider rounds, the KMS allowance, and fixed transport/CPU slack. A lease must exceed the entire request deadline by at least five seconds. The default two-claim/two-concurrent batch has one provider round; the 45-second worker deadline remains below the 50-second caller deadline, which remains below the 55-second outer wake-up and 60-second function ceiling. The committed defaults are in `.env.example`.

The remainder of this section describes `aws-kms` mode only. The AWS trust policy must pin OIDC audience `sts.amazonaws.com`. At runtime Vercel places its workload OIDC token in the `x-vercel-oidc-token` request header. The explicit header check is only a bounded presence guard: the Vercel AWS provider reads the token from request context, exchanges it through STS, and the worker proves real GenerateDataKey + Decrypt access against the active AI object-wrap root before issuing a request-scoped authority. That opaque authority cannot be recreated with an object literal. It exposes only a revocable object-wrap generate/unwrap facade backed by the dedicated `index_worker` key workload; AI content-MAC and every private binding are rejected before KMS. Every operation rechecks live authority and forces a composite of the original request signal and a private lease-revocation signal. Retained references fail after abort/completion, outstanding custody calls are actively aborted on normal scope completion, and revocation occurs before the KMS session closes. The raw token is never passed to the drain port, returned, or logged.

Do not configure static `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, or `AWS_SESSION_TOKEN`. The worker must obtain short-lived credentials through Vercel OIDC. Do not configure `UNFILED_AI_CONTENT_MAC_KMS_KEY_ARN`, any retired AI content-MAC/broad AI registry, `UNFILED_PRIVATE_OBJECT_WRAP_KMS_KEY_ARN`, `UNFILED_PRIVATE_CONTENT_MAC_KMS_KEY_ARN`, or legacy singular key IDs. Its AWS role permits only `kms:DescribeKey`, `kms:GenerateDataKey`, and `kms:Decrypt` against AI-assisted object-wrap generations, explicitly denies every AI content-MAC and private-manual generation, and has no rewrap action. Bind the AWS trust policy to the exact issuer, `sts.amazonaws.com` audience, and `sub`; a project or team prefix match is insufficient.

Account setup must also enable and retain environment-attributed CloudTrail evidence for the worker's STS/KMS use, including the encryption context needed by the security drills. The implementation does not claim that a worker-specific audit stream exists until that setup has been completed and verified. Preview and Production infrastructure, provider usage, paid database hardening, and retained audit evidence can incur charges and require the account owner's approval before provisioning.

Preview and Production do not accept the local bearer and reject both `UNFILED_WORKER_DRAIN_SECRET` and `CRON_SECRET`. Configure Vercel Deployment Protection Trusted Sources as two exact same-environment rules: web Preview may call only worker Preview, and web Production may call only worker Production. Forward the caller token in `x-unfiled-trusted-oidc-idp-token`. The worker independently verifies the RS256 signature and pins the team issuer, default team audience, exact subject, owner slug/ID, project name/ID, selected environment, `iat`, `nbf`, and one-hour maximum lifetime. It rejects `Authorization` and `x-vercel-protection-bypass` instead of treating either as a fallback. The worker's separate `x-vercel-oidc-token` AWS workload token is never caller authentication.

Vercel's contract documents the Trusted Sources request header but does not guarantee in the cited setup text that it remains visible after Deployment Protection verification. Before enabling either environment, run a deployed same-environment probe that records only pass/fail and proves the header reaches the function. If it is absent, this implementation returns `401`; do not add a bearer or bypass fallback. Platform Trusted Sources remains mandatory even though the function also performs cryptographic verification.

The process also refuses known user-session variables, private-manual KMS variables, every non-empty environment variable whose name contains `SUPABASE`, and conventional ambient database variables such as `DATABASE_URL`, `POSTGRES_URL`, and `PGPASSWORD`, even in local mode. A linked integration can inject JWT-signing or database capabilities that bypass the worker's RPC-only role, so none may enter this trust domain. The only database capability admitted is the deliberately named, exact-role `UNFILED_WORKER_DATABASE_URL`. Vercel project separation and the database/IAM/KMS policies remain the authoritative capability boundary.

## Remaining managed-environment gate

1. Configure each exact same-environment Vercel Trusted Sources rule, deploy the content-free header-visibility probe, and preserve environment-attributed account evidence.
2. Provision the one exact-role TLS worker login and CA in the approved remote beta database, enter it explicitly in both managed secret scopes, and keep provider projects/models/credentials environment-specific. Run the account-bound identity/allowlist probe from each deployment before allowing any real job.
3. The web project already sends only `{ "trigger": "schedule" | "recovery" }` with `x-unfiled-trusted-oidc-idp-token`; use Vercel's authenticated management plane to prove each exact alias belongs to this worker project and deployment environment before configuring that sensitive caller origin, then verify the daily recovery cron. Runtime cannot infer project ownership from an alias, so never substitute an adjacent project-ID assertion or downgrade either managed environment to a bearer, `CRON_SECRET`, deployment-bypass secret, forwarded user token, or forwarded workload token.
4. Exercise wrong-project OIDC, private-key deny, KMS/provider/database outage, timeout/abort, lease recovery, v1→v2 rotation, response-loss replay, header preservation, and CloudTrail audit tests.
5. Complete the generation seed and independent strict-decrypt verifier lifecycle before activating a shadow generation. Complete the separate atomic organizer and retire the same-deployment legacy organizer before claiming workload isolation.

The Preview or Production rollout is incomplete until those lifecycle and account-bound gates are green for that exact environment. This runtime alone is not evidence that the complete note library is encrypted, and neither custodian mode makes any data end-to-end encrypted or zero-knowledge. The statements in this README describe what the checked-in code and its local tests enforce; they are not deployment evidence.
