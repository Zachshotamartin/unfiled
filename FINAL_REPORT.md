## 2. Provider, model, and effort contract (ADR-0015)

| Control              | Values                                                                                                                                           | Where enforced                                                                                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Provider             | `openai`, `anthropic`                                                                                                                            | Contracts (Zod), database `ai_provider` enum, iOS `AIProvider`                                                                                                     |
| Model                | `auto`, `gpt-5.6-luna`, `gpt-5.6-terra`, `gpt-5.6-sol`, `claude-sonnet-5`, `claude-opus-5`                                                       | `organization_model_selection` enum; `private.organization_model_matches_provider`; contracts `isAiModelSelectionForProvider`; iOS `AIModelSelection.isCompatible` |
| Automatic resolution | OpenAI: economical→Luna, standard→Terra, thorough→Sol; Anthropic: economical/standard→Sonnet 5, thorough→Opus 5                                  | `private.resolve_organization_model_id` at job creation; organizer `resolveOrganizerModelId` revalidates the claim                                                 |
| Effort               | `economical`, `standard`, `thorough` → provider-native `low`, `medium`, `high`                                                                   | Organizer adapters (`reasoning.effort`, `output_config.effort`)                                                                                                    |
| Behavior             | `cautious`, `balanced`, `automatic`                                                                                                              | Existing routing policy                                                                                                                                            |
| Expansion            | `off`, `brief`, `detailed`                                                                                                                       | Existing generated-block policy                                                                                                                                    |
| Managed fallback     | Off by default; offered only when `UNFILED_MANAGED_AI_FALLBACK_AVAILABLE` (web) / `UNFILED_MANAGED_AI_FALLBACK_AVAILABLE` xcconfig (iOS) says so | Web view model, iOS `ManagedFallbackContract`; the free beta leaves it unavailable                                                                                 |

Job snapshots (`organization_job_ai_settings`) immutably record `selected_provider`, `model_selection`, `model_id`, `routing_effort`, `expansion_style`, `settings_revision`, and `adapter_registry_version = organization-model-registry-v2`; the organizer claim projection exposes exactly 23 keys and the lease-bound credential route exactly 10 keys, and both are rejected on any drift. Keys never appear in jobs, claims, logs, responses, or evidence.

Provider adapters:

- OpenAI: `POST https://api.openai.com/v1/responses`, bearer key, strict Structured Outputs, `store: false`, `model` from the job snapshot, `reasoning.effort` low/medium/high, 20 s deadline, one retry for transport/408/409/429/529/5xx.
- Claude: `POST https://api.anthropic.com/v1/messages`, `x-api-key`, `anthropic-version: 2023-06-01`, `output_config.effort`, one forced strict tool derived from the OpenAI schema, exactly one matching `tool_use` block accepted; text-only, zero/multiple/wrong tool calls, `max_tokens`, refusals, and non-object inputs defer to Review.
- The credential's provider selects the adapter; tests prove an OpenAI key is never sent to Anthropic, a Claude key is never sent to OpenAI, and neither reaches retrieval.

## 3. Free-beta custody and retrieval (ADR-0016)

- Custodian `vercel-sensitive-env-v1`: four independently generated 32-byte AES-256 roots (AI object-wrap, AI content-MAC, private-manual object-wrap, private-manual content-MAC) stored only as Vercel Sensitive Environment Variables, bound to the exact project ID and `production`. Web holds all four; organizer holds the two AI roots; worker, verifier, and search hold AI object-wrap only. Root material never leaves Keychain/Vercel; only root IDs appear in the metadata registry.
- Retrieval embeddings: `unfiled-local-hash-v1`, 512 dimensions, a deterministic feature-hash vector computed in process. It keeps note and query text away from any provider merely for retrieval and needs no provider key, but it is not a semantic embedding and ranks weaker than one. Exact-title, rule, and lexical paths remain the primary destinations.
- AWS KMS/Terraform is preserved and validated (26 tests) but not applied; it is deferred paid hardening.
